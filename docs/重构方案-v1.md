## 一、现有资产盘点（重构要整合的全部内容）

## 四、推荐结论

**分两步走（风险最小、收益最大）：**

**第一步（必做）：原生精修 = 方案 A**
- 基于 `index-v2.html`（黑金）继续做"丝滑"改造：
  - 引入 **GSAP**（局部引入，不打包）：Hero 入场时间线、滚动视差、价格数字滚动升级、卡片入场 stagger
  - 字体（Bahnschrift 已有）+ 视差光效 + Canvas 粒子/噪点（可选）
  - 保持 api-bridge 契约，后端零改动
- 产出：**马上能用、马上丝滑**的版本，2~3 天

**第二步（按需）：组件化 = 方案 B**
- 若后续要加：多店铺 / 素材上传 / 存单 / 消息通知 / 移动端 H5
- 用 Vite + Vue3 + TS + Tailwind + GSAP 重写展示层，API 复用，admin 同步 Vue 化
- 契约为后端侧保留一份，前端不再依赖注入式 bridge

> 若你想一步到位"全栈主流"，直接选 **D（Next.js）**；但请接受：现有 Fastify 路由、OCR 服务、双驱动 DB 都要搬到 Next 生态，工期最长。**对单人维护的自助下单站，A→B 是最优解。**

## 六、风险与待决策

1. **参考可达性**：本环境 GitHub / Codrops 被网络限制，需你在浏览器里亲自浏览 2.1 / 2.2 清单再反馈偏好。
2. **收款码是个人码**：OCR 对账是当前唯一可行方式；若接入微信/支付宝商户号（回调置 paid），OCR 可退役。
3. **api-bridge 契约**：选 A 完全保留；选 B/C/D 需重新设计前端数据层，后端 API 可原样复用。
4. **黑金 vs 霓虹**：当前推荐黑金（`index-v2.html`）；若参考站看到更心动的风格，P0 阶段可改 tokens 重新出。
5. **动效性能**：GSAP 全量加载约 60KB gzip，建议只引需要的模块（ScrollTrigger 等）。
